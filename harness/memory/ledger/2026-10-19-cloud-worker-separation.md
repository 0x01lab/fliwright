## Decision

Host Workers are CLI-started Node.js processes deployed independently of the centralized Cloud Server. Worker owns device scanning/reporting, execution, process supervision, cleanup and upload retry; Cloud owns persistent scheduling, policies, reports and browser administration. Shared wire contracts, inferred device snapshot types, HTTP client and artifact upload policy live in cloud-protocol, which imports neither runtime nor native discovery. Configuration and credential loading stay local to each deployment.

The Worker production graph has no Cloud Server, SQLite, Fastify or React requirement. Cloud is a Worker development dependency only for real HTTP integration tests. Runtime isolation checks block Server/SQLite imports in Worker and host execution imports in Cloud. Production deployment uses the private workspace package with pnpm deploy --legacy --prod; npm installation is not available until packages are published.

Move owned tests with the implementation. Keep lease fencing, owned process-group termination, evidence preservation and explicit recovery semantics intact. Remove replaced Cloud Worker commands and exports; use fliwright-cloud-worker run/discover/recover/retry-uploads, updating deploy templates and browser deployment hints together. Each execution slot still needs its own process and root, and enrollment does not start an executor.
