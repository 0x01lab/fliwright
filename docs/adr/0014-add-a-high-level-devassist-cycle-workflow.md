# Add a high-level DevAssistCycle workflow

Fliwright exposes a high-level `fliwright_devassist_cycle` MCP workflow for local development assistance. Its optional natural-language `request` is the highest-priority expression of the behavior to verify; when absent, Fliwright derives bounded intent from the workspace change. The first call creates a `devAssistSessionId`; follow-up calls use it to reuse the same inferred test intent, candidate test, and assertions after source edits. When a candidate is structurally invalid, Fliwright returns `needs_regeneration` with evidence and requires an explicit regeneration request rather than silently replacing the test. The workflow uses the existing provider-neutral `AiRuntime`, initially configured with local Codex or Claude CLI adapters rather than a new model service. It uses the TDD runtime's automatic reload/restart decision, escalating a failed reload to at most one restart and recording the decision in DevAssistTrace. On a red cycle it performs one passive AI diagnosis and returns that diagnosis in the same trace, without modifying source or recursively invoking the model. It orchestrates focused-test selection, app synchronization, execution, failure evidence, diagnosis, and the next-cycle parameters while leaving application source edits to the external AI coding agent. Existing lower-level MCP tools remain available for advanced agents and debugging. This gives common agents one stable contract without duplicating the underlying TDD and run-report capabilities.
