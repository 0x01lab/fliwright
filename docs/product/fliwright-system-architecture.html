配置归属与实现依据
  • 项目仓库：fliwright.config.ts、vitest.config.ts、tests、scenarios 与 mocks；CLI、Vitest、编辑器复用项目配置。
  • Worker 私有主机：worker.json、credentials.json、Flutter / SDK、只读仓库凭据、平台所需 resetCommands；配对 run 后跟随网页设备绑定管理槽位。
  • Flutter App：专用测试入口初始化 Bridge；根据业务场景注册路由、存储重置与 auth.seedLoggedIn。
  • 本地执行可以直接连接本机或可达的 Flutter App；它与云端执行是替代入口，不表示可同时控制一台设备。
  • 依据：harness/architecture/README.md；packages/fliwright-cloud/src/config.ts、CloudStore.ts、ReportStore.ts；packages/fliwright-cloud/deploy/nginx.conf.example；packages/fliwright-cloud-worker/src/host.ts、worker.ts 及 README.md。

02 · MODULES & RELATIONSHIPS

模块职责与协作关系

顺着箭头看协作：云端安排任务，主机启动执行，入口复用引擎，引擎通过 Bridge 操作 App。也可以从本地入口直接运行。

图中表示主要协作关系，未穷举所有包导入。VS Code 插件独立展示：复用 CLI 的配置与执行能力，并直接调用 Core 的交互能力。同框合并 Vitest / TDD、Devices / Native 与 Riverpod 两端；Test Plan 与 Design QA 见下表。cloud-protocol 是共享通信库，由 Server 与 Worker 使用。

模块如何配置到一起

配置归属配置 / 接入点连接哪些模块
项目配置fliwright.config.ts → vitest.config.ts
tests / scenarios / mocks		CLI 与编辑器复用项目配置；Vitest 通过 fliwrightPreset(projectConfig) 接入，场景在测试前准备 App 状态。
VS Code 插件安装 Fliwright 扩展
打开项目；配置 fliwright.* 设置并连接 App		通过 CLI 解析项目配置和执行测试；通过 Core 建立自动化会话，提供录制、Mock、状态面板与证据查看；可选接入 Riverpod 插件与 TDD 状态视图。
App 接入Flutter 测试入口初始化 Bridge
按需注册路由、重置与业务状态能力		Core 通过 VM Service 连接 Bridge；鉴权场景由 App 提供 auth.seedLoggedIn 等状态准备能力。
云端与主机server.json / worker.json
网页配置项目、套件与设备绑定		Cloud 管队列与租约，Worker 按绑定管理执行槽位，经 CLI 执行项目；双方通过 cloud-protocol 约定消息与上传格式。
状态与执行扩展plugins: [riverpodPlugin()]
Dart Riverpod 观察器；TDD 入口		Riverpod 需要 TS / Dart 两端配合；TDD 由 CLI / 编辑器接入，复用 Vitest 与 Core，保持聚焦执行会话。
设备与设计扩展平台工具与 Native 会话配置
fliwright_design_qa（Labs，可选）		Devices 提供设备清单，Native 提供原生 UI 会话；Design QA 在 App 内接入，通过配对将截图传到 Figma Hub。
验收与自动化绑定GitLab 验收快照 / 测试计划文件Test Plan 记录验收项与已有测试的对应关系；执行仍由 CLI / Vitest 承担。
