FLIWRIGHT为什么使用

把重复操作，变成可以复用的流程

从“每个人手动再做一遍”，走向“用同一套流程执行、验证和讨论”。

常见协作问题Fliwright 提供什么谁直接受益
修改后反复点击相同业务路径TypeScript 自动化脚本、断言与重复执行开发 / 测试
空数据、异常返回和特定用户状态难复现命名场景、Mock 规则和 App 自有状态准备开发 / 测试
失败时只知道“没通过”，缺少上下文步骤、截图、快照、错误与 Trace 证据开发 / 测试
测试结果只在执行者电脑上离线 HTML 报告、Cloud 回放与受控分享产品 / 设计 / 全团队
多人争用设备，运行状态不透明团队队列、Worker 槽位与设备管理测试 / 效能 / 管理者
产品价值把操作过程、运行环境和结果证据连在一起，让业务验证可以重复，也方便同事一起检查。

FLIWRIGHT能做什么

功能全景：覆盖自动化的六个环节

CLI 是主要执行入口；VS Code 提供日常工作界面；Cloud 提供团队运行与协作。

同一套运行时

脚本、测试、编辑器和云端执行复用底层自动化能力。

按需求选配

网络 Mock、Riverpod、原生设备能力和 Cloud 按项目接入；AI / Flow / Design QA 属于实验方向。

FLIWRIGHT工作原理

它怎样理解并操作 Flutter App

App 接入 Bridge 后，工具可读取 Widget 语义与上下文，使用定位器执行操作并检查结果。

接入前提团队需要控制 App 源码，在专用调试 / 测试入口启用 Bridge，并提供可访问的 VM Service；Release 模式下 Bridge 不启用。

FLIWRIGHT编写与录制

从一次操作，沉淀成可维护的自动化

录制帮助搭建流程；业务断言与真实回放决定它能否成为可信回归测试。

脚本：完成任务

例如打开某页、填写表单、重复准备演示环境；流程不一定需要测试断言。

测试：判断业务对错

在操作之后检查“保存成功”“值已持久化”等可观察结果；缺少确认断言不能当作已验证测试。

录制的输出TypeScript 为主要路径；另有 Dart 生成能力，Dart 的验证需要独立的编译 / 回放证据。

FLIWRIGHT环境复用

同一套业务流程，可以切换不同场景

用命名、可继承的 TestScenario 声明环境，减少测试各自拼装前置条件。

适合准备什么

存储种子、登录身份、App 能力、状态适配、Mock、路由和就绪检查。实际可用项取决于 App 接入。

身份如何准备

已登录业务测试通过 App 自有的 auth.seedLoggedIn 注入测试身份；登录流程本身单独验证。

设备权限、媒体、相机等声明有独立平台与接入限制，类型存在不代表端到端可执行。Cloud 构建器当前主要组合 Mock 与起始路由，导出配置后需提交仓库。

FLIWRIGHT数据可控

Mock：让难复现的数据情况稳定出现

可选的 HTTP / WebSocket Mock，让同一业务路径在不同返回数据下重复验证。

示例规则用户会看到什么建议验证什么
profile-success正常用户资料字段显示正确，允许编辑
profile-empty资料为空或缺失空态文案、占位与可用操作
profile-error读取或保存失败错误提示与重试入口
复用与断言规则以 JSON 维护，可组合共享与专项规则，并检查请求是否发生及其参数。直接运行且未选场景时，Cloud 不自动加载 Mock。

FLIWRIGHT结果与证据

失败后，沿着证据回到具体一步

运行结果之外，还能查看步骤和上下文，帮助团队讨论“在哪里、为什么失败”。

本地复盘

CLI 与 VS Code 查看运行记录；从保存的结果生成可离线打开的 HTML 报告，无须重跑 App。

团队查看

Cloud 按已归档步骤与截图回放，支持拖动时间游标和只读分享；这不是连续视频录屏。

业务结论与证据完整性分别展示：测试通过不代表证据齐全；中断、缺图和部分证据应保留其真实状态。

FLIWRIGHT接入与限制

能力边界：先认清范围，再选择接入

当前为 Developer Preview。下面区分已有能力、选配条件与仍需专项验收的范围。

能力当前定位同事需要知道的条件
定位 / 操作 / 断言 / 运行证据核心需要 Bridge 与可信调试 / 测试构建
录制与代码生成已有能力可靠测试仍需稳定目标、断言和候选回放验证
网络 Mock / Riverpod / VS Code可选集成按项目接入；Riverpod 写入需要明确可写注册
Cloud / Worker / GitLab 触发已有独立部署能力身份、仓库、设备、重置和部署链路需本地验收
ADB / XCTest 原生 UI可选能力，按平台验收模拟器已有受控验证；真机与具体系统场景单独确认
设备权限 / 相机 / 生物识别受限能力 / 专项接入不承诺各平台声明均可端到端执行
AI 修复 / TDD / Flow / Design QALabs启用与平台适配需配置；输出需审阅和验证

Android / iOS 模拟器及 macOS 各有已验证切片；不能据此推断所有平台、手势、输入法或真机均已完整支持。版本与平台细项参见兼容性记录 [S16]。

团队落地顺序

第三步 · 团队运行接 CI 或 Cloud；配置设备、Worker、身份与报告分享。
