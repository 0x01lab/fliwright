# Worker 自动绑定与执行环境同步

用户只需配对本机、启动一次 `fliwright-worker run worker.json`，然后在网页选择纳管设备和允许的应用。常驻主机进程同时负责设备发现、目录扫描和执行器同步。

- 纳管设备未填写槽位 ID 时，服务端按设备稳定注册 ID 自动生成槽位；保留用户显式填写的 ID。
- 已纳管、启用设备的应用关联自动成为该主机的目录扫描范围，不要求编辑 Server JSON。
- 认证后的 Worker 只能读取自己的设备执行分配。分配不包含凭据或任意远程命令。
- 最小配对配置可直接用于 `run`。主机自动推导身份、本地运行目录，为分配创建独立目录和控制连接，并在网页配置变化时同步执行器。
- 默认 iOS 模拟器重置为 shutdown、boot、bootstatus，保留数据，不执行 erase。用户选择了“自动重启模拟器，保留设备数据”。其他设备可以使用本机显式配置的 resetCommands；没有可用重置策略时只扫描和报告设备，输出具体原因。
- 移除、禁用或更改绑定时停止对应执行器；隔离槽位不会自动恢复或重放执行尝试。使用中的槽位仍遵守既有禁止重新绑定规则。
- 网页以自动绑定为默认，槽位 ID 是高级选项，不再要求用户逐设备部署 Worker 进程。`discover` 保留为明确的仅发现诊断命令。

验证覆盖空槽位自动绑定、幂等保存、应用范围撤销、扫描授权、Worker 身份隔离、配对配置直接运行、网页变化后的执行器启动/停止、无空闲轮询和干净退出。
