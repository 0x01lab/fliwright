# Self-Healing Pipeline

> When a widget selector breaks between recordings, automatically suggest a replacement selector by comparing the last-known good widget snapshot against the current widget tree using a weighted multi-dimensional similarity score.

## Architecture

1. **Assertion runs** (`Assertion`): each `expect(locator).toBeVisible()` style call polls the locator; on success it records the matching widget snapshot for the `(testName, selector)` pair via `SelfHealingEngine.recordSuccess`.
2. **Baseline storage** (`SnapshotStore`): persists the last-known-good `WidgetSnapshot` keyed by `testName + selectorString` to disk under `.fliwright/snapshots/`.
3. **Failure detection** (`Assertion`): on assertion failure after timeout, the assertion calls `SelfHealingEngine.tryHeal` before throwing.
4. **Candidate fetch** (bridge `SnapshotExtension`): the engine asks the running Flutter app for the current interactive widget tree via `ext.fliwright.snapshot`.
5. **Multi-dimensional scoring** (`MultiDimensionalHealingStrategy`): each candidate is scored on four dimensions — `position` (Euclidean distance), `context` (neighbors Jaccard), `codeBinding` (key/type/finder-code similarity), `text` (n-gram similarity of labels). Dimensions are weighted and combined into a single confidence value.
6. **Match decision**: the highest-scoring candidate above the threshold is returned with a suggested selector generated by `SelectorResolver.resolveSelector`.
7. **Re-execute assertion** (`Assertion`): if healing succeeded, a new `Locator` is built from the suggested selector and the original assertion retried once.
8. **Report retention** (`SelfHealingEngine.reports`): every heal attempt is stored with timestamp, scores, original/suggested selectors, and the matched widget. Reports are surfaced via the MCP `fliwright_get_failure` tool.

## Agent Integration

- The pipeline is **transparent** to test authors: write normal assertions and healing runs automatically when a baseline snapshot exists.
- MCP agents call `fliwright_get_failure` after a test failure to read the latest healing report (suggested selector + per-dimension scores + confidence) and rewrite the failing test source.
- `SelfHealingEngine.setEnabled(false)` disables the pipeline for deterministic runs.

## Data Flow

```
Assertion (poll) ──ok──> SelfHealingEngine.recordSuccess ──> SnapshotStore.save (.fliwright/snapshots/*.json)
       │
       fail after timeout
       ▼
SelfHealingEngine.tryHeal
   ├── SnapshotStore.load (baseline)
   ├── bridge ext.fliwright.snapshot (candidates)
   └── MultiDimensionalHealingStrategy.heal
         ├── scoreDimensions (position / context / codeBinding / text)
         └── pick best above threshold
              │
              ▼
      SelectorResolver.resolveSelector ──> new Locator ──> retry assertion
              │
              ▼
      HealingReport (kept in memory + surfaced via MCP)
```

## Key Files

- `packages/fliwright-core/src/Assertion.ts` — assertion wrapper that triggers healing on timeout.
- `packages/fliwright-core/src/SelfHealingEngine.ts` — orchestrates baseline storage, candidate scoring, and report retention.
- `packages/fliwright-core/src/SnapshotStore.ts` — disk-backed snapshot persistence.
- `packages/fliwright-core/src/strategies/MultiDimensionalHealingStrategy.ts` — scoring algorithm and `ngramSimilarity` helper.
- `packages/fliwright-core/src/SelectorResolver.ts` — converts a matched `WidgetInfo` into a stable selector.
- `packages/fliwright-bridge/lib/src/extensions/snapshot.dart` — Dart side of `ext.fliwright.snapshot` RPC.
- `packages/fliwright-mcp/src/tools/getFailure.ts` — MCP surface for reading healing reports.
